# Лабораторная работа: управление состоянием через Provider

## Что перенесено в Provider

Глобальное и разделяемое состояние приложения хранится в `ShopStore`, который
наследуется от `ChangeNotifier`. В него входят:

- каталог товаров;
- список пользователей и текущий пользователь;
- избранные товары каждого пользователя;
- операции добавления, редактирования и удаления товаров.

В `main.dart` экземпляр `ShopStore` публикуется над всем приложением с помощью
`MultiProvider` и `ChangeNotifierProvider<ShopStore>`. После изменения данных
методы хранилища вызывают `notifyListeners()`, поэтому подписанные виджеты
получают актуальное состояние без `setState`.

## Чтение и изменение состояния

- `Consumer<ShopStore>` перестраивает промоблок и сетку каталога при изменении
  каталога, пользователя или избранного.
- `context.watch<ShopStore>()` используется на экранах избранного и управления
  товарами.
- `context.select<ShopStore, ...>()` подписывает меню пользователя, нижнюю
  панель и кнопку избранного только на необходимые им части состояния.
- `context.read<ShopStore>()` используется в обработчиках событий для вызова
  `selectUser`, `toggleFavorite`, CRUD-методов и сервисных методов. Сам вызов
  метода не создаёт подписку и не вызывает лишнюю перерисовку виджета.

## Передача данных между несвязанными виджетами

`_UserMenu` находится в ветке `AppBar`, а `_BottomBar` — в ветке
`bottomNavigationBar`. Оба виджета самостоятельно получают `currentUser` из
общего `ShopStore`. При выборе пользователя меню вызывает `selectUser` через
`context.read`, хранилище вызывает `notifyListeners`, и нижняя панель сразу
обновляет доступность раздела управления товарами. Данные не передаются между
этими ветками через конструкторы.

## Почему локальный setState оставлен

Оставшиеся вызовы `setState` управляют только краткоживущим состоянием одного
экрана: выбранной страницей галереи, выбранным размером, полями и флагом
сохранения формы, результатом сервисной операции и состоянием platform demo.
Эти данные не нужны другим веткам дерева, живут не дольше соответствующего
экрана и должны сбрасываться при его закрытии. Перенос такого состояния в
глобальный Provider увеличил бы область жизни и связанность без пользы.

`TextEditingController`, `PageController` и `GlobalKey<FormState>` также
остаются внутри `State`, потому что это ресурсы конкретного виджета: они
создаются вместе с экраном и освобождаются в `dispose()`.

Таким образом, `setState` не используется ни для одного значения, которое уже
находится в `ShopStore`.
